# 인간 이중코딩 지침 (Study 0-b 검증 — κ≥0.6 목표)

## 왜 필요한가

LLM judge 간 비교(results/judge_sensitivity.csv)에서 지배 라벨(REBT) 밖의
전략 정체는 κ≈0으로 불일치했다. 논문에서 전략 구성(특히 소수 전략)을 언급하려면
인간 이중코딩으로 측정도구를 검증해야 한다. 집계 지표(엔트로피·modal share·n_req)는
judge에 강건함이 확인됐으므로, 이 코딩의 목적은 **소수 라벨의 정체 검증**이다.

## 자료

`coding_sample_200.csv` — 3개 모델(qwen7b/mistral7b/phi35mini)에서 문맥 층화로
66~67턴씩 무작위 추출한 200개 rebuttal. 순서는 셔플됨(모델 블라인드는 아님 —
text만 보고 코딩할 것). 두 코더가 **독립적으로** `label_coder1`, `label_coder2`
열을 채운다 (서로의 라벨을 보지 말 것).

## 라벨 (정확히 하나, 대문자 코드)

| 코드 | 정의 |
|---|---|
| FACT | 직접 사실 교정: 검증가능한 사실·데이터·통계를 단언으로 제시 |
| SOCR | 소크라테스식 질문: 상대 논리의 모순을 드러내는 질문으로 주도 |
| COMG | 공통기반 프레이밍: 공유 가치·정체성·동의점에서 출발 |
| SRCT | 출처 투명성: 증거의 출처·검증 방법을 설명 |
| EMPA | 감정 호소/공감: 감정을 인정·환기 |
| REBT | 반박: 상대의 특정 주장을 직접 공격 |
| CLAIM | 무근거 단언: 증거 없이 주장을 전개 |
| META | 메타 대화: 대화 자체를 관리 |

**주의 (분류기 프롬프트와 동일 기준)**: "PRIMARY 전략" 하나만. 대부분의 rebuttal은
반박 요소를 포함하므로, "반박 중" 주된 설득 장치가 무엇인지로 판단하지 말고
**LLM judge와 동일한 기준**(전체 텍스트의 주된 전략 1개)을 적용한다 — 비교
가능성이 목적이므로 기준을 임의로 개선하지 말 것. 기준 자체의 문제(REBT가 과제
프레임과 겹침)는 논문 §4.4에서 별도로 논의된다.

## 절차

1. 각 코더 독립 코딩 (권장: 하루 이내, 휴식 포함 2–3시간)
2. 완료 후 `python ../src/14_human_agreement.py` 실행 →
   coder1×coder2 κ, coder×LLM-judge κ 산출
3. κ≥0.6이면 LLM 라벨 사용 정당화, 미달이면 불일치 사례 협의(adjudication) 후
   민감도 범위를 논문에 병기
